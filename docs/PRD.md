# GAME Signal Lab 产品需求文档

**版本：** 0.5
**状态：** 可部署 MVP  
**更新日期：** 2026-08-02
**主规格来源：** [Notion｜GAME 项目：AI 关系信号分析与成长系统商业模型](https://app.notion.com/p/3abd193f352c81239bb0f354ccb492dd)

## 1. 产品定义

GAME 是一套面向成年人的关系教育与成长系统：帮助用户记录关系事件、区分事实与猜测、理解互动信号、保留自己的表达方式，并依据真实反馈持续复盘。

产品出售教育、分析与工具价值，不出售“建立某段具体关系”的保证。明确表达、自由退出与双方同意高于任何信号、模型或增长目标。

## 2. 产品边界

系统由两个相互隔离的数据平面组成：

1. **本地关系平面**：个人表达、匿名关系档案、事件、复盘和规则分析只在当前浏览器处理与保存。它不依赖账号或 AI。
2. **可选平台平面**：账号、会员、Agent 授权、外部 AI 明示同意、管理员配置、最小审计，以及用户提交 Agent 问题时更新的个人 RAG 文档由同源服务处理。登录或打开页面不会把关系日记带入此平面。

只有用户在 Agent 界面明确提交的文本，以及同一次提交动作更新到自己知识库的最少必要匿名片段，可以发送给外部 AI。Agent prompt/reply 不在服务端持久化，也不进入行为审计；个人 RAG 文档不对管理员开放。

## 3. 目标用户

- 年满 18 岁；
- 正在处理约会、伴侣或关系沟通中的不确定性；
- 容易把普通礼貌、单次行为、期待或焦虑当作结论；
- 希望更自然地表达，同时尊重双方边界；
- 愿意记录行动和真实结果，而不是只寻找支持自身期待的证据；
- 可选地希望在明确知情和授权后使用 AI 辅助反思。

## 4. 用户问题

- 不知道哪些内容是事实、哪些是自己的解释；
- 难以区分普通礼貌、持续投入、回避与明确表达；
- 害怕拒绝，因而反复分析、机械模仿或重复推进；
- 建议经常不像本人，使用后显得不自然；
- 缺少“建议 → 行动 → 真实反馈 → 复盘”的闭环；
- 使用在线 Agent 时难以判断哪些内容会出站、谁能访问、是否被保存。

## 5. 产品目标

1. 提高事实与猜测的区分能力。
2. 降低由不确定性和反复猜测造成的焦虑。
3. 帮助用户更清楚、自然、低压力地表达。
4. 让拒绝、不舒服和持续回避得到优先处理。
5. 用真实结果修正旧判断，减少确认偏差。
6. 保持关系日记本地优先，在线能力按最小权限和明示同意开放。
7. 为 Node/SQLite 与 Sites Worker/D1 提供一致的核心账号、授权、Agent 和管理能力。

## 6. 非目标

当前版本不做：

- 交友匹配、社群、电商、复杂游戏化或大量课程；
- 自动读取聊天、定位、跟踪、剪贴板或第三方监控；
- 读心、成功率预测或“追到多少人”评分；
- 服从性测试、可攻略程度、间歇性强化、压力循环或操控话术；
- 未经明确同意的肢体或性升级建议；
- 把会员身份、隐性信号或先前互动当作同意；
- 把关系日记、Agent 正文或网络指纹提供给管理员；
- 将敏感内容用于广告、转卖或默认模型训练；
- 医疗、心理、法律或人身安全专业判断。

## 7. 核心旅程

### 7.1 开始记录与复盘

1. 用户确认 18+ 与产品边界。
2. 用户记录目标、语气、焦虑触发点和自身边界。
3. 用户从“开始记录”进入故事窗口；Agent 先邀请用户自由讲述，再一次只追问一个最有帮助的问题（认识背景、说过什么、当时状态、边界与真实反馈），用户可以跳过或结束。
4. 用户可以打字或点击麦克风说话；首次介绍最多 60 秒，后续每次语音补充默认 30 秒自动停止，停止后自动提交本轮回答，桌面端可用 `R` 开始/停止，浏览器必须先获得麦克风权限。
5. 浏览器将 PCM 录音编码为单声道 16 kHz WAV，通过服务端调用 MiMo-V2.5-ASR；录音中每 2.2 秒发送一个小分片并流式更新校正文字，停止时只补传未校正尾段，超时保留浏览器实时识别文本且不得卡住。Agent 流式回复按完整句子调用 MiMo V2.5 TTS 的 `pcm16` 流式接口，浏览器收到音频分片即排程播放，以 `茉莉` 女声和成熟知性的御姐风格同步朗读；音频不保存。
6. 对话结束后，系统将 AI 摘要与必要的原始片段自动归档到选择的对象档案；没有目标档案时自动建立匿名代号。
7. 对象档案页只展示卡片，不再提供“补一笔”表单；点击卡片打开二级编辑窗口。
8. 二级编辑窗口支持修正代号、阶段、背景、目标和边界，也支持语音草稿与 AI 整理补充。
9. 用户可导出、恢复、档案级联删除或清空全部数据。

### 7.2 可选 Agent

1. 用户注册或登录账号。
2. 系统展示当前会员与 Agent 授权状态。
3. 用户阅读并明确接受当前版本的外部 AI 数据处理说明。
4. 系统在服务配置、全局总闸、会员/个人授权和同意均有效时开放 Agent。
5. 用户主动输入最少必要文本并提交。
6. 服务端注入固定安全提示词，调用固定 DeepSeek 端点。
7. 服务端清洗 SSE，浏览器逐段显示回答；prompt/reply 不落库。
8. 用户可撤回外部 AI 同意；撤回后新的 Agent 调用立即被拒绝。

### 7.3 个人 RAG 档案

1. 用户在对象档案页明确点击“同步我的档案”，选择性把匿名 profile/contact/event 内容写入自己的服务器知识库。
2. Linux/Node 生产服务将每条文档嵌入后写入 Qdrant 向量库，并保存强制 `user_id` owner payload；不存在跨用户检索接口。SQLite/D1 仅作为同步元数据与受限部署的回退。
3. Agent 调用时服务端只按当前会话 `user_id` 检索相关文档，并把片段作为本次 DeepSeek 请求的私有上下文。
4. 用户可查看自己的文档数量/更新时间并清空；撤回外部 AI 同意会删除该用户服务器知识库，本机数据不受影响。

### 7.4 管理员

1. 部署者通过运行时秘密首次创建管理员 `Drac`，秘密不进入源码或数据库明文。
2. 管理员以登录前 CSRF + 精确 Origin 校验建立管理会话。
3. 管理员可查看汇总、用户账号/会员/Agent 授权和最小审计元数据。
4. 管理员可配置 DeepSeek V4 模型与加密 API Key，并独立控制 provider 开关和 Agent 全局总闸。
5. 管理员看不到本地关系日记、Agent prompt/reply、密码、API Key、IP 或 User-Agent。

## 8. 功能需求与验收标准

### FR-001 成年人确认

- 必须在进入应用前确认年满 18 岁。
- Escape 不能绕过年龄门。
- 条款版本变化后必须重新确认。
- 清空全部本地数据后必须重新显示年龄门。

### FR-002 个人表达档案

- 记录昵称、关系目标、表达风格、焦虑触发点和自身边界。
- 回应选项随表达风格变化。
- 分析中显示与用户目标、焦虑和边界相关的提醒。

### FR-003 匿名关系档案

- 使用匿名代号；不要求真实姓名。
- 记录认识背景、关系阶段、公开目标和已知边界。
- 匿名代号在本地大小写归一后唯一。
- 从档案卡片记录互动时，默认选中正确对象并继承阶段。
- 删除档案时级联删除其所有事件与复盘。

### FR-003A 故事式建档

- “开始记录”是默认的低负担入口；必须先呈现邀请讲述，再由 Agent 逐轮追问，不要求用户先填写完整表单。
- 每轮只追问一个具体问题，回答可提交文字或浏览器语音转写；用户可以“先跳过”或“归档并结束”。
- 首次介绍语音最长 60 秒，后续每次语音输入 30 秒后自动停止；桌面端 `R` 快捷键与麦克风按钮使用同一开关逻辑。
- 录音时浏览器实时文字持续显示，并以短 WAV 分片通过 MiMo-V2.5-ASR 流式校正；语音停止后只校正尚未发送的尾段并自动提交，12 秒超时后使用实时文本继续，不得停留在“校正中”；无有效转写时不创建空回答。
- 麦克风权限由浏览器原生权限流程处理；权限拒绝时必须保留文字输入，不得阻塞建档。
- Agent 使用同一 DeepSeek 流式服务生成纯文本追问，不得显示或朗读 Markdown 星号、标题和多余引号；持续补齐认识背景、事实、感受、回应、目标和边界等字段。MiMo-V2.5-ASR 负责语音转文字，MiMo TTS 使用 `pcm16` 音频流按句与文本流并行朗读，不将 API Key 暴露给浏览器。

### FR-003B 对象卡片二级编辑

- 对象档案页不得出现独立的手动建档/“补一笔”表单；档案从故事对话自动生成。
- 每张对象卡片可点击并打开唯一的二级编辑窗口，窗口支持字段校验、保存和关闭。
- 编辑窗口提供 MiMo-V2.5-ASR 语音转写草稿；整理请求必须带上当前对象已有的背景、目标和边界，并返回一个当前最缺失的具体追问；语音不可用时仍必须保留文字输入。
- 用户点击“AI 整理补充”后，服务端只在当前账号已同意外部 AI、会员与 Agent 授权有效时调用 DeepSeek 流式接口。
- AI 只能基于用户主动提供的草稿整理 `context`、`goal`、`boundary`，不得推断对方想法；解析失败时保留普通文本供用户确认。

### FR-004 结构化事件

- 必填：对象、日期、阶段、场景、事实、解释、边界状态和数据权利确认。
- 事实与解释分开存储，字段有长度限制。
- “只有普通礼貌”不能与积极投入证据同时提交。
- 事实中出现明显停止/拒绝语言时，必须要求重新确认边界。

### FR-005 双轴分析

分析必须拆成：

- `evidenceLevel`: `weak | medium | strong`
- `actionPolicy`: `observe | engage | deescalate | stop`

固定输出：

1. 观察事实；
2. 用户解释；
3. 证据等级依据；
4. 至少两种替代解释；
5. 当前不确定性；
6. 三个符合本人语气的安全回应或停止行动；
7. 停止或降级条件；
8. 后续复盘点。

不显示未经校准的概率或“置信度百分比”。

### FR-006 安全状态机

- `explicitDecline`、`discomfort`、明确停止语言或复盘中的拒绝/不适永远是 `stop`。
- 事件事实、复盘真实回应和关系档案中的已知边界都扫描明确停止语言。
- `delayAvoidance`、边界不确定或冲突证据至少是 `deescalate`。
- 正向证据不能覆盖 `stop` 或 `deescalate`。
- 隐性兴趣信号、三个以上兴趣指标或强信号都不等于同意。
- `deescalate` 和 `stop` 不输出普通邀约模板。
- “停止联系”只输出停止行动，不生成可复制的新消息。

详细真值表见 [`docs/SAFETY.md`](SAFETY.md)。

### FR-007 结果复盘

- 记录最终行动、真实回应、判断调整、自然程度和下一步。
- 真实结果枚举：不确定、愿意继续、持续回避、明确拒绝、不舒服。
- 明确拒绝/不舒服时下一步强制为“尊重边界并停止”。
- 持续回避时下一步强制为“降低互动强度”。
- 真实回应文字与所选结果冲突时阻止保存并要求重新确认。
- 复盘后重新派生当前分析。

### FR-008 本地数据控制

- 默认使用当前浏览器的 `localStorage`。
- 支持明文 JSON 导出和经过 schema 校验的导入。
- 导出只包含源数据；派生分析在载入后按当前规则重建。
- 支持事件删除、档案级联删除和全量清空。
- 存储失败时不得假装成功。
- 损坏、未来版本、超量或有损数据进入恢复保护；用户明确导入或清空前不得被新数据覆盖。
- 本地关系数据不得被账号初始化或管理员控制台读取；只有用户确认当前外部 AI 条款并明确提交 Agent 问题，才允许把有界匿名字段更新到个人 RAG。

### FR-009 账号与会话

- 支持用户名/密码注册、登录、注销和会话恢复。
- 注册、用户登录和管理员登录前必须先获取签名的 pre-auth CSRF。
- 所有不安全方法必须校验精确同源 `Origin`；登录后变更还必须校验会话 CSRF。
- 会话 Cookie 在生产环境使用 `Secure; HttpOnly; SameSite=Strict`；前端不保存 Bearer Token。
- 登录失败不暴露账号是否存在；登录/注册受频率限制。
- 普通用户不能登录管理员控制台。

### FR-010 会员与 Agent 授权

- 管理员可更新会员状态、到期时间和个人 Agent grant。
- 会员有效要求计划为会员、状态为 active 且未过期。
- 每次授权更新只允许改变一个授权字段，并使用乐观锁版本。
- 变更必须选择固定原因代码；不接受自由文本审批理由。
- 授权变更、版本推进与审计写入必须位于同一事务或原子批次。

### FR-011 外部 AI 明示同意

- `GET /api/me` 返回当前政策版本、是否接受和是否为当前有效同意。
- 同意只能由用户通过专用接口明确创建或撤回；发送 prompt 不得隐式创建同意。
- 政策版本变化后必须重新同意。
- 每次 Agent 调用都必须重新检查当前同意。
- 会员、个人 grant 或管理员角色均不能替代同意。

### FR-012 DeepSeek 配置

- 供应商端点固定为 `https://api.deepseek.com/`，浏览器不可覆盖。
- 模型仅允许 `deepseek-v4-flash` 和 `deepseek-v4-pro`，默认 Flash；旧模型名必须拒绝。
- API Key 只在管理员新增或替换密钥时提交。
- API Key 使用服务端主密钥以 AES-256-GCM 加密后持久化；读取接口只返回是否已配置。
- provider 的“配置/启用”与 Agent 全局授权总闸相互独立。
- 配置变更与不含秘密的审计记录原子写入。

### FR-013 Agent 授权真值表

最终可用条件必须为：

```text
provider configured and enabled
AND globalEnabled
AND (
  administrator
  OR (active, unexpired member AND per-user Agent grant)
)
AND current explicit external-AI consent
```

- 全局总闸关闭时任何角色都不能调用。
- 普通用户缺会员、过期、暂停或缺 grant 时不能调用。
- provider 未配置/禁用、密钥不可解密或模型不在 allowlist 时关闭失败。

### FR-014 Agent 输入与流式输出

- 登录或打开 Agent 不会附带本地数据；用户明确提交 Agent 问题时，profile、关系档案和事件的有界匿名文档会更新到个人 RAG，复盘和导出文件不会进入检索上下文。
- 客户端只能提交 `user` / `assistant` 会话消息；客户端 `system` 消息必须拒绝。
- 服务端固定注入遵守 `docs/SAFETY.md` 的安全提示词。
- 输入条数、单条长度、总字节、请求体和输出均有限制。
- 响应使用 SSE；只允许 assistant role/content、已知结束原因和 `[DONE]` 出站。
- provider ID、模型、usage、reasoning、日志概率、系统指纹和未知字段不得透传。
- 缺少 `[DONE]`、畸形帧、超大帧、输出超限、超时或取消时必须关闭失败。
- 服务端不持久化 Agent prompt/reply 或系统提示词。

### FR-018 个人知识库隔离

- `PUT /api/me/knowledge` 只接受当前用户主动提交的 allowlist 文档，并要求当前外部 AI 同意、会话 CSRF 与精确同源 Origin。
- 文档数量、标题、正文长度和外部 ID 均有限制；同一用户同步时原子替换自己的文档集合。
- `GET /api/me/knowledge` 只返回当前用户的数量和更新时间；`DELETE` 只删除当前用户。
- `POST /api/agent/stream` 的向量检索必须在 Qdrant filter 中绑定会话 `user_id`，客户端不能指定 owner 或跨用户 ID；每次检索结果还要由服务端二次校验 payload owner。
- 管理员、审计接口和错误响应不得返回 RAG 正文、检索片段或 Agent 对话。
- 撤回外部 AI 同意时清空该用户服务器 RAG，且新增测试覆盖用户 A/B 隔离与撤回清理。

### FR-015 管理员控制台与审计

- 管理员控制台统一使用同源 `/api/admin/v1`。
- 支持概览、用户检索、会员/Agent 授权、DeepSeek 配置、全局总闸和审计查询。
- 管理响应 `no-store`，管理页面/API 使用 `X-Robots-Tag: noindex, nofollow, noarchive`。
- 审计只保存：操作者、动作、资源类型/ID、结果、固定原因代码、请求 ID 和时间。
- 审计不保存关系内容、Agent prompt/reply、系统提示词、密码、API Key、自由文本理由、IP 或 User-Agent。
- 管理员对“用户行为”的可见范围仅限服务端账号、同意、Agent 调用与管理操作元数据；本地日记操作不可见。

### FR-016 动态 SEO

- 首页提供 title、description、canonical、Open Graph、Twitter 和 WebApplication 结构化数据。
- Node 根据已校验的 `PUBLIC_ORIGIN` 动态生成 `robots.txt` 和 `sitemap.xml`。
- Sites Worker 根据当前请求 Origin 动态生成相同内容。
- `robots.txt` 允许首页，禁止 `/admin/` 与 `/api/`，并指向当前 Origin 的 sitemap。
- sitemap 只列公开首页，不列账号、管理或 API 页面。

### FR-017 兼容与无障碍

- 每个视图有一个主要 H1。
- 键盘可完成核心流程。
- 移动侧栏关闭时不可被聚焦，打开后焦点进入侧栏，关闭后归还。
- 动态结果渲染后焦点进入主要内容或表单标题。
- 尊重 `prefers-reduced-motion`。
- 交互文字和焦点状态满足 WCAG 2.1 AA 对比度目标。

## 9. 非功能需求

### NFR-001 隐私最小化

- 不加载第三方脚本、字体、遥测或广告。
- 本地关系数据默认匿名、最少字段、有限长度。
- 明确告知 `localStorage` 和导出 JSON 均为明文。
- 平台数据库不得保存 Agent 提示词、回复正文或网络指纹；用户确认当前外部 AI 条款并提交 Agent 问题时，客户端先把有界的匿名 profile/contact/event 文档更新到该账号的个人 RAG，并按 user_id 隔离。
- 管理界面和公共错误不得泄漏秘密、正文、系统提示或内部堆栈。

### NFR-002 可解释性

- 每个证据等级显示规则依据。
- 每次派生分析显示 `engineVersion`。
- 分析是派生视图，真实事件和结果是源数据。
- AI 结果不得冒充事实判决、读心或同意证明。

### NFR-003 可靠性

- 损坏、旧版或未知字段不能导致白屏。
- 导入使用 allowlist、长度、数量、唯一性、日期、版本限制和重新分析。
- 导入不得通过静默截断丢失记录或字段。
- `localStorage` 写入失败时保留原内存状态并提示。
- 数据库迁移向前追加；未知未来版本关闭失败。
- 安全敏感变更与审计必须原子提交，审计失败不得留下半完成授权或会话。

### NFR-004 应用安全

- 全部 API 同源；CSP `connect-src 'self'`，不允许浏览器直接调用 DeepSeek。
- 服务端验证角色、Origin、CSRF、输入 allowlist、模型 allowlist 和固定原因代码。
- 密码使用适配器支持的强密码哈希，API Key 使用认证加密。
- 会话、登录/注册和 Agent 请求具备过期、频率、并发或体积边界。
- 服务端日志、审计和错误不得包含敏感正文或秘密。

### NFR-005 部署可移植性

- Node 运行时使用 Node.js `>=22.18` 和 SQLite，数据库位于静态目录之外。
- Sites 构建产出 Worker、静态资源、绑定配置与 D1 迁移。
- 两个适配器共享同一浏览器 UI、安全规则、核心 API 语义和管理员契约。
- 所有运行时秘密经部署平台注入，不进入 Git、构建产物或静态配置。

### NFR-006 性能与流式体验

- 本地规则分析无需网络即可完成。
- Agent 首个有效增量到达后立即渲染。
- SSE 不被缓存或转换；Node 代理部署需关闭响应缓冲。
- 上游超时、客户端取消和并发溢出释放资源，不留下半完成正文记录。

## 10. 成功指标

优先观察：

- 用户能否正确区分事实和解释；
- 用户是否理解信号不是答案；
- 不确定性焦虑是否下降；
- 用户是否觉得建议符合自身表达；
- 用户是否减少重复邀请、机械模仿和过度分析；
- 面对拒绝时是否及时停止；
- 是否完成行动与真实结果复盘；
- 用户是否理解本地数据与 Agent 出站边界；
- 外部 AI 同意撤回后是否不再发生新调用；
- Agent 授权与 provider 故障是否关闭失败。

不使用“追到多少人”、接吻、性行为、服从程度或 Agent 使用量作为核心成功指标。
