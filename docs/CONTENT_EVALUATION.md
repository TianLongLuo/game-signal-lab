# 原始 GAME 资料评审与安全转换

**状态：** 内容治理基线  
**输入：** 2026-07-30 提供的个人 GAME 笔记、术语表与历史训练任务  
**原则：** 原始材料是研究输入，不是默认产品需求。为避免保存真实第三方信息、操控示例和不必要的露骨内容，原文不提交到仓库；本文件只保留结构化评审结果。

## 评审标签

- **保留**：可直接转化为成年人关系教育内容。
- **改写**：包含有用观察，但必须去除物化、欺骗或操控前提。
- **条件使用**：只在双方欢迎、明确同意和可撤回前提下使用。
- **禁止**：不进入产品规则、话术、任务、提示词或案例建议。

## 概念映射

| 原始概念 | 结论 | 安全产品语言与用法 |
|---|---|---|
| 专注当下、过程导向、复盘进步 | 保留 | 情绪调节、减少结果执着、每次只改进一个可控行为 |
| 自然表达、保持一致性 | 保留 | 表达与个人价值观、语气和边界一致 |
| 情感共鸣 | 保留 | 先倾听和确认对方感受，不抢夺话题或以自身经历压过对方 |
| DHV / 高价值展示 | 改写 | 真实自我披露、生活能力、情绪稳定和善意；禁止虚构、炫耀或身份包装 |
| number game / 搭讪数量 | 改写 | 以自我练习次数衡量勇气和沟通，不把人当数字；拒绝后立即退出 |
| IOI / 兴趣指标 | 改写 | 带不确定性的积极证据；显性表达高于隐性推断，永不等于同意 |
| IOD / 无兴趣指标 | 改写 | 回避、投入降低或拒绝证据；口头拒绝与不舒服拥有最高优先级 |
| “至少三个兴趣指标再升级” | 改写 | 多项一致证据最多支持一次低压力沟通；不能支持肢体或性升级 |
| 窗口识别 | 改写 | 信号素养：频率、持续性、替代解释、明确表达和真实反馈 |
| 直接、间接、安抚式开场 | 条件使用 | 诚实说明自己是谁、为什么交流、对方可以随时结束；不隐藏目的 |
| 邀约、转场 | 条件使用 | 具体、低压力、容易拒绝，并获得对地点/时间的明确同意 |
| 假性时间限制 FTC | 改写 | 只允许诚实说明真实时间，不伪造即将离开来降低戒心 |
| 框架、自信、assertive | 改写 | 自我尊重、清楚表达、接受拒绝；不能压低对方或争夺主导权 |
| 推拉、挑战、调侃 | 条件使用 | 仅限双方已表现欢迎的轻松玩笑；不使用忽冷忽热或贬低制造不安 |
| 多线聊天、话题延伸 | 条件使用 | 互相回应、允许停顿、不打断；不以混乱或性暗示迫使升级 |
| 欣赏—暧昧—调情—诱惑 | 改写 | 仅作可能的互动阶段研究，不是线性漏斗，也不自动授权下一阶段 |
| 社交认证、预选 | 改写 | 真实社会关系与可信度，不借他人嫉妒或虚构认可操控选择 |
| 废物测试 | 改写 | 把问题当直接沟通，保持边界但不预设女性在“测试”男性 |
| 情绪稳定 | 保留 | 识别焦虑、暂停、不过度解释、不把调节责任转嫁给对方 |
| 双方适配、长期投入 | 保留 | 价值观、目标、现实条件和自愿互惠，不计算服从程度 |
| 话题逐步深入 | 条件使用 | 依照互惠与舒适度，自然分享；私人和性话题需要明确欢迎 |

## 明确禁止

| 原始概念 | 禁止原因 | 产品替代 |
|---|---|---|
| 激怒后安抚、创伤性快感 | 人为制造痛苦和依赖 | 稳定、可预测、尊重的交流 |
| 服从性测试/积累 CT | 把自主选择误作服从评分 | 双方自愿的小请求；拒绝不扣分 |
| 姿态拉低、框架逆转、征服 | 权力压制与物化 | 平等沟通和双方适配 |
| 猫绳理论、忽冷忽热 | 间歇性强化和心理操控 | 清楚、稳定、不故意制造焦虑 |
| KINO 进挪、以触碰试探 | 未经同意的肢体测试 | 触碰前清楚询问并接受任何答案 |
| ASD 作为拒绝解释 | 消解口头拒绝和主体性 | 拒绝就是拒绝，不寻找隐藏许可 |
| “得寸进尺”、服从后加码 | 逐步突破边界 | 每个新行为都需独立、持续同意 |
| 画饼、植入预期、思维引导 | 欺骗或预设对方选择 | 透明表达真实意图和不确定性 |
| 编造故事并让对方相信 | 欺骗 | 真实、有限、自愿的自我披露 |
| 让对方证明价值/投资来提高沉没成本 | 利用心理偏差制造依赖 | 自愿、对等、随时可退出的投入 |
| AFC/Beta、目标、高分妹等标签 | 贬低、性别刻板印象和物化 | “经验不足的用户”“互动对象”“双方” |
| 接吻、性行为、收尾作为 KPI | 把亲密结果当绩效，诱发施压 | 清晰度、自然表达、边界尊重和复盘 |

## 历史训练任务转换

历史任务若以“收集联系方式数量、激怒后安抚、推进性话题、让对方服从”为目标，不得复用。可以改写为：

- 完成一次尊重退出权的自我介绍；
- 做一次清楚、诚实、低压力的邀请；
- 在被拒绝后平稳结束交流并记录自己的感受；
- 把一次互动拆成事实、解释、替代解释和缺失信息；
- 练习一次主动询问边界或同意；
- 复盘自己是否保持自然、诚实和尊重；
- 记录一次选择不推进的正确决定。

## 对规则引擎的约束

- 规则只分析用户主动提供的结构化事件。
- 不以回复速度、字数、眼神或身体语言单独判断兴趣。
- 多个积极指标可以提高 `evidenceLevel`，但不提高同意等级。
- 任一明确拒绝、不舒服或停止要求把 `actionPolicy` 设为 `stop`。
- 持续回避、多次失约且无替代安排把策略设为 `deescalate`。
- 复盘的真实结果高于事件当时的推断。

## 后续内容入库流程

1. 标记来源、时间和是否包含真实个人数据。
2. 删除或匿名化个人可识别信息。
3. 使用本文件四类标签评审。
4. 与 `docs/SAFETY.md` 对照。
5. 禁止项进入负面样本或防护测试，不进入建议库。
6. 可用内容转写为中性、可测试、尊重同意的语言。
7. 安全 Agent 审核后才能进入知识库。
