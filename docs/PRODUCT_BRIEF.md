# GAME 产品需求简报

## 一句话定义

GAME 是一套面向成年人的关系教育与成长系统：帮助用户记录关系事件、区分事实与猜测、理解互动信号、保留自己的表达方式，并根据真实反馈持续复盘。

## 产品立场

- 不神化导师，不复制某个“高手人格”。
- 不承诺帮助用户“拿下”某个具体的人。
- 不把关系对象当作销售线索或可攻略目标。
- 不用职业、收入、外表或服从性定义人的“质量”。
- 不突破明确拒绝、边界或自由退出权。
- 明确表达和双方同意高于任何信号分析与模型输出。
- AI 是可选的反思助手，不是读心器、裁判或关系结果保证。

## 用户问题

用户的核心焦虑不是缺少一句万能回复，而是：

- 不理解关系如何发展；
- 不知道哪些是事实、哪些是自己的猜测；
- 看不懂普通礼貌与特别关注的区别；
- 不知道如何自然表达兴趣；
- 害怕拒绝，因此反复分析或机械模仿；
- 缺少把行动、反馈和结果连接起来的复盘系统；
- 使用 AI 时不清楚数据会发给谁、是否保存和如何撤回。

## 诊断模型

### 1. 机会数量

- 是否有自然、双方自愿的互动机会；
- 是否拥有稳定的社交场景；
- 是否长期处在封闭、重复的人际环境中。

### 2. 双方适配

- 价值观、生活方式和关系目标是否协调；
- 双方是否存在真实兴趣；
- 沟通节奏与现实条件是否允许继续发展。

### 3. 信号识别

- 能否区分单次行为与持续模式；
- 能否区分自己的期待与实际证据；
- 能否识别主动、投入、回避与明确表达的变化。

### 4. 回应沟通

- 能否自然回应而不是突然使用陌生话术；
- 能否清楚表达兴趣，同时保留对方拒绝的空间；
- 能否面对拒绝并及时停止推进。

## 分析输出结构

每条事件的本地分析固定包含：

1. 观察事实；
2. 用户解释；
3. 至少两种替代解释；
4. 证据等级与依据；
5. 当前不确定性；
6. 自然、低压力的回应或停止行动；
7. 停止或降级条件；
8. 后续复盘点。

规则引擎将“证据强不强”和“现在该不该推进”拆成两个轴。即使证据较强，只要存在拒绝、不舒服、持续回避或边界不确定，行动策略仍必须降级或停止。

## 当前产品形态

### 本地关系平面

第一层验证七个核心能力：

1. 用户目标与个人表达风格；
2. 匿名关系档案；
3. 互动事件记录；
4. 事实与推测分离；
5. 证据分级、行动策略与替代解释；
6. 三个自然、低压力的回应或停止行动；
7. 行动、真实结果与复盘记录。

这层不需要账号、不需要网络，也不依赖 AI。数据保存在当前浏览器，支持明文 JSON 导出、恢复、删除和清空。

### 可选平台平面

第二层提供：

- 账号与会员；
- 个人 Agent grant 和全局总闸；
- 当前版本外部 AI 数据处理明示同意；
- DeepSeek V4 流式 Agent；
- 管理员用户/授权/配置与最小行为审计；
- Node/SQLite 和 Sites Worker/D1 两种部署。

关系日记不上传。只有用户在 Agent 中明确提交的文本会出站；服务端不持久化 prompt/reply，管理员也看不到正文。

## Agent 的产品角色

Agent 的价值不是生成“更强话术”，而是：

- 帮用户把事实、解释与情绪拆开；
- 补充不同于用户当前期待的替代解释；
- 把拒绝、不舒服和停止联系置于最高优先级；
- 把表达改成更自然、低压力且容易拒绝的形式；
- 提醒用户减少第三方隐私输入；
- 在高风险场景停止给关系推进建议。

Agent 最终可用需要同时满足 provider、全局总闸、会员/个人授权和当前外部 AI 同意。付费或角色不能绕过同意。

## 当前不包含

- 交友匹配；
- 大型社群；
- 电商商城；
- 复杂游戏化；
- 大量关系课程；
- “保证脱单”或“保证建立关系”的销售承诺；
- 自动读取第三方聊天记录；
- 第三方定位、跟踪或监控；
- 服从性、可攻略程度或性结果评分；
- Agent 对本地关系日记的自动抓取；
- 记录 Agent 对话正文或按对话内容做广告画像。

## 管理与运营边界

管理员控制面服务于授权、配置、安全与故障排查，不是内容监控后台。

管理员可以看到：

- 账号和加入时间；
- 会员状态、到期时间、个人 Agent grant；
- provider 配置状态、模型和全局总闸；
- 账号、同意、Agent 调用和管理变更的最小审计元数据。

管理员看不到：

- 本地关系档案、事件、分析和复盘；
- Agent prompt/reply；
- 密码、API Key、IP 或 User-Agent。

这让商业运营可以配置会员能力，同时保持关系内容与运营后台隔离。

## 商业路径

### 阶段一：本地工具与问题验证

- 通过具体关系问题吸引用户；
- 用本地记录、分析与复盘验证使用频率；
- 观察事实/解释分离和真实结果闭环是否创造价值；
- 沉淀完全虚构或取得合法授权的案例结构，不沉淀用户私人正文。

### 阶段二：会员与可选 Agent

- 免费层保留核心本地能力；
- 会员获得经过授权的 Agent 使用资格；
- 管理员用 global + member + grant 控制灰度；
- 复杂问题转交有资质的人工支持，而不是无限扩大模型权限。

### 阶段三：知识资产

- 建立关系问题分类体系；
- 建立去标识、授权清楚的高质量案例库；
- 形成证据等级、替代解释和边界风险标注标准；
- 将经验从个人表达转化为可审计、可测试的方法。

### 阶段四：品牌与生态

- 小组复盘和沟通训练；
- 关系主题活动；
- 关系记录手册、沟通卡片与内容出版物；
- 核心产品得到验证后再考虑社群或生活方式产品。

## 获客方向

先从一个高频问题切入，而不是宣传“解决所有关系问题”：

- 看不懂对方是否愿意继续了解；
- 聊天后不知道下一步怎么做；
- 容易把礼貌误判成兴趣；
- 有机会但表达不自然；
- 重复进入相似的不健康互动。

推荐内容结构：

> 具体事件 → 常见误判 → 原因 → 多种解释 → 自然回应 → 边界提醒 → 真实结果复盘

初期渠道可以包括朋友圈、小红书、独立站和线下一对一服务。内容不得使用真实聊天截图或可识别第三方信息作为“战绩”。

## 品牌与视觉方向

品牌应当是“产品 IP”，不是“导师 IP”。用户最终记住的是：

- 一套稳定的分析模型；
- 一组清楚的产品功能；
- 一套克制、可信的视觉符号；
- 尊重主体性、边界与真实反馈的价值观。

视觉采用“人文叙事 × 电子杂志”方向，并根据工具场景收敛：

- 衬线字体用于标题、叙事与关键判断；
- 无衬线字体用于表单、控件和长说明；
- 等宽字体用于状态、编号、版本与审计元数据；
- 暖纸色、深靛蓝和克制蓝绿强调；
- 细分隔线、直角卡片与高信息密度代替浮夸动效；
- 安全警告清楚但不羞辱用户。

可用品牌语言：

- 看懂信号，保留自己。
- 不是教你成为别人，而是帮助你更清楚地理解关系。
- 从混乱走向清晰。

## 核心资产

真正壁垒不是聊天界面或某个模型，而是：

- 关系问题本体与分类系统；
- 同时包含成功和失败、且来源合法的高质量案例；
- 稳定的证据与风险标注体系；
- 保留用户主体性的个性化模型；
- 建议、行动、反馈、复盘组成的闭环；
- 可验证的同意、授权与审计模型；
- 对敏感关系数据的长期安全与信任。

## 衡量指标

- 用户是否更能区分事实和猜测；
- 对关系不确定性的焦虑是否下降；
- 是否更敢于清楚、礼貌地表达；
- 是否减少机械模仿和过度分析；
- 建议与真实反馈的吻合和修正程度；
- 是否尊重拒绝并及时停止；
- 建议是否符合用户自己的语言和人格；
- 是否持续完成记录与复盘；
- 用户是否理解本地/出站数据边界；
- 同意撤回与授权撤销是否立即生效。

不使用“追到多少人”、接吻、性行为、服从程度或 Agent 使用时长作为核心成功指标。

## 后续待验证

1. 第一批用户最愿意为哪个具体问题付费；
2. 用户愿意记录到什么程度；
3. 哪些字段真正有助于判断，哪些只是噪音；
4. 如何衡量建议是否符合用户本人；
5. 如何获得真实结果反馈；
6. 哪些问题必须转交人工顾问；
7. 免费本地工具、付费会员与 Agent grant 的边界；
8. 账号导出/删除、同意历史与密钥轮换机制；
9. 如何避免用户形成对 AI 的依赖；
10. “GAME”是否适合长期品牌，以及中文名称如何定义。
