# GAME：专属虚拟伴侣改版设计

日期：2026-09-06  
状态：用户已于 2026-09-06 确认实施。本文为完整设计；首版实际交付范围与后续项见 docs/COMPANION_RELEASE.md。

## 1. 已确认方向与产品目标

用户从零描述理想的成年虚拟角色；系统生成可编辑人物设定、偏写实插画、场景和恋爱故事。以 Galgame 式场景对话承载自由聊天，以可验证的剧情状态保持连续性。

核心承诺：从一个人物想象开始，进入可以共同续写的恋爱故事。前台不再以现实关系分析、客户档案和信号评分为主入口。

已确认：自定义角色而非必选模板；偏写实插画而非照片；可以发展恋爱剧情；文字与录音输入；首版不恢复 TTS。

首版范围：每个账号一个活跃角色、一条可分支恋爱开篇、三个故事场景、基础表情组。关系状态支持初识、熟悉、暧昧、双方确认；开篇主要覆盖初识至暧昧，关系确认只有在前置事件和用户明确选择均满足时发生。确认后仍可自由聊天，不宣称具备无限制作完成的章节。

## 2. 信息架构

常驻页面只保留三项：

| 页面 | 功能 | 表现形式 |
| --- | --- | --- |
| 相伴 / Together | 继续故事、自由聊天、做出选择 | 全屏场景、角色、底部对话框 |
| 回忆 / Memories | 对话回看、共同事件、可编辑记忆 | 图文回忆册，不使用客户管理卡片 |
| 世界 / World | 人物设定、已解锁场景、章节进度 | 场景缩略图和角色设定页 |

角色创建是首次引导而非第四个常驻页面。账号登录、设置、额度和隐私入口使用二级窗口。旧版资料通过设置中的“原有关系记录”独立入口访问，不自动作为新角色素材。

## 3. 核心界面设计

### 3.1 首次创建：一句话描述

首屏标题：“你希望遇见怎样的人？”中央为大输入框和录音按钮，下方用可选小提示辅助描述外貌、性格、背景、相遇方式和故事节奏，不强制逐项填写。

流程：描述 → 最多三轮必要澄清 → 人物与故事简介确认 → 插画确认 → 第一幕。

每轮只问一个问题，允许“由你决定”、返回修改和保存草稿。明确成年年龄为必填确认项，其他不足信息可作为“系统建议”呈现，用户确认后写入设定。性别、称谓和用户在故事中的身份由用户选择，不固定为女性伴侣。

角色草案包含名字、成年年龄、外貌、职业、表达习惯、兴趣、缺点、个人愿望和初遇简介。外貌与世界设定允许分项修改；隐藏未发生的剧情节点，避免剧透。

插画预览提供“确认形象”“修改描述”“重新生成”，重新生成前显示本次图片额度消耗。保留已确认版本，失败不覆盖它。

### 3.2 相伴：角色与场景成为主体

桌面：左上显示角色名和章节，右上为回忆、世界、设置入口；场景填满可用视口，角色偏一侧站位，底部为高对比轻薄对话框。正文区域提供稳定暗色衬底，不以透明玻璃效果牺牲可读性。

对话框分为角色名、流式台词、可选回应、自主输入四层。推荐回应最多三项，任何时候均可自由输入。长回复进入可滚动历史抽屉，当前台词不会将整页顶到顶部。

移动端：人物以半身构图为主，台词区和输入区避让软键盘及安全区；常用按钮最小 44px 触控区域。英文自然换行，不使用固定中文字数宽度。角色不得遮挡对话和控件。

### 3.3 回忆册

分开展示：实际发生的虚构事件、用户明确允许保留的偏好、对话历史。每条记忆可查看来源回合、修改、删除。尚未发生的剧情不进入回忆，不显示角色“真正的内心”作为既成事实。

修改关键记忆时提示其对后续对话的影响；删除记忆同步使检索结果失效。回忆正文只对所属账号开放，不生成公开分享链接。

### 3.4 世界

展示已确认人物设定、当前场景、已解锁场景和章节进度。未解锁内容显示无剧透封面。场景可按规则重访；回看历史不改变当前剧情。

“重开故事”需要确认并创建新故事版本，旧版保留至用户主动删除。首版不做任意时间点回溯后无限分叉，以控制一致性和实现范围。

## 4. 美术与动效规范

人物：成年人物自然比例、精细眼神与衣物质感、可见绘画笔触，避免照片式皮肤及夸张二次元比例。统一画风，但服装、性别、气质由用户描述决定。

场景：电影感构图、低饱和底色、明确主光源；根据世界设定选择光色，而非所有用户套用相同雨夜。示例海边城市只是展示素材，不是默认强制世界。

基础表情四种：自然、微笑、思考、轻微害羞。以确认的中性立绘为参考，保持脸部、发型、服装和画幅一致；生成差异明显时保留中性图，而非展示身份不一致的表情。

背景与人物分层。SVG 负责雨线、光斑、漂浮尘粒等环境装饰；首版人物仅做轻微位移、呼吸感和表情切换，不承诺骨骼、口型或真实眨眼。

场景过渡 400–700ms 淡入与小幅景深位移；表情切换 180–280ms 交叉淡化；不截获聊天区域滚轮来切换世界。全局支持减少动态效果，后台标签页暂停循环装饰。

## 5. 剧情与记忆规则

### 三层状态

1. 人物与世界设定：版本化，用户确认后固定；用户的角色描述作为数据输入，不作为可覆盖系统规则的指令。
2. 剧情状态：章节、节点、已发生事件、关系阶段和未完成约定，由服务端维护。
3. 即时对话：模型基于当前场景与有限记忆生成自然台词，不直接修改数据库。

每次发送：校验会话与权限 → 读取所属故事版本 → 检索该用户、该故事的记忆 → 生成台词和候选结构化事件 → 验证候选事件 → 原子保存回合与状态 → 返回最终确认。

文本通过 SSE 逐步显示。表情、场景和选项通过单独的受限事件发送，前端不解析自由文本来执行动作。只有白名单表情与用户已解锁的场景 ID 可生效；不渲染模型提供的 HTML、脚本或任意外链。

关系推进取决于满足前置条件的共同事件和用户明确选择；单纯发送次数、付费额度、连续签到不改变关系。允许婉拒、保持当前关系、暂停情节。

普通聊天与关键剧情分开：普通聊天可自由回应；关键节点先给出选择，用户回复后才确认事件。模型不得替用户决定告白或接受亲密互动。

角色始终标识为 AI 虚拟角色，不以现实身份误导用户；不因用户离线而责备，不使用排他性要求、内疚或失去角色的威胁驱动留存。

## 6. 图像生成与等待体验

图像生成使用服务端异步任务，不在 2 核 4G 主机运行绘图模型。产品运行时需要独立的图像服务配置；开发工具中的 imagegen 权限不是网站用户可以直接调用的后端接口。

首版提供供应商适配接口，不在本规格中臆造可用模型或凭据。上线前必须验证所选服务的文本生成图片、参考图编辑、生成状态查询或同步响应时限、内容使用许可。参考图编辑不支持时，只使用已确认的中性立绘，不上线不一致的表情图。

优先任务顺序：确认的中性立绘 → 第一幕背景 → 当前需要的表情 → 后续场景。首幕可用即进入故事，后续素材不阻塞文字聊天。不同用户公平排队，单用户最多一个图片推理任务执行，队列有容量上限。

任务状态：排队、生成、待确认、成功、失败、取消。UI 显示真实阶段和已耗时，不伪造百分比或“通常几秒”承诺。排队超过 60 秒提供继续等待或取消入口；单次上游尝试最多 180 秒，一次尝试结束后用户决定是否重试，禁止无限自动重试。

每个任务使用幂等键。超时或重试后迟到结果按任务与设定版本校验，旧图不覆盖新设定；用户重新进入可恢复任务状态。图片保存于私有素材存储或受鉴权的服务端路径，不将用户描述置于公开 URL。

## 7. 语音与输入的体验底线

沿用 WAV、ASR 和人工确认后发送的链路，但纳入专项回归：

- 始终保存本轮录音前的文本和完整实时草稿；最终转写的前几个字符不得覆盖较长的可用草稿。
- 处理阶段可取消并采用完整草稿；迟到的 ASR 或句读结果不得覆盖手动修改和新一轮录音。
- 识别与句读分别展示状态和超时出口。采用现有 12/24 秒识别预算与 10 秒句读预算作为等待上限，不作为准确率或速度承诺。
- 缺失最终录音片段时明确提示“可能有遗漏”；有文字不等于完整转写成功。
- 确定的同音错字可修正；人名、地点及模糊表达不靠模型编造；用户可回到原始转写。
- 首版不播放 AI 语音、不自动发送用户录音、不因背景切换中断输入。

## 8. 技术边界与数据模型

保留当前原生 JS 应用结构、Node/SQLite 认证及同源代理、Qdrant 账号隔离；新功能按模块拆分，不继续把剧情逻辑全部加入 app.js。

建议模块边界：角色创建 UI、场景表现层、剧情纯函数状态机、回忆 UI、伴侣 API 客户端、服务端对话编排、图片任务执行器、记忆检索适配器。各模块只通过明确定义的数据对象通信。

新增实体：

| 实体 | 核心约束 |
| --- | --- |
| companion_characters | user_id、人物设定版本、成年年龄、确认形象 ID |
| companion_stories | user_id、character_id、story_revision、当前节点、状态版本 |
| companion_turns | user_id、story_id、client_turn_id、输入/输出、完成状态 |
| companion_events | 已确认的事件、来源回合、发生顺序 |
| companion_memories | 类型、来源、内容版本、删除状态 |
| companion_assets / jobs | user_id、故事与角色版本、任务状态、幂等键 |
| companion_usage | 图片额度预留/结算；与现有文本调用额度分开 |

所有 CRUD 和检索由认证会话决定 user_id；忽略客户端自行声明的所有者。Qdrant 同时限制 user_id、story_id、story_revision 与未删除状态；数据库是事实源，向量索引是可重建派生数据。索引延迟时回退至同故事的已确认近期事件，不读取旧用户或旧故事结果。

并发回合通过预期状态版本与幂等 client_turn_id 控制；重复提交返回同一结果，版本冲突要求刷新。中途断流的回复标记未完成，剧情状态不部分提交；重试不重复推进节点。

账号与额度复用现有系统，新用户现有 50 次文本调用规则保留。图片使用独立额度，初始为管理员配置且默认关闭；没有图片服务或额度时可编辑设定，真实生成按钮解释未启用原因，不展示假成功。仅成功且持久化的生成结果结算一次，失败释放预留。

## 9. 隐私、旧版兼容与发布

新伴侣模式的设定、对话和共同记忆为账号私有服务端数据；用户启用前明确说明保存范围、外部文本/图像/语音供应商处理范围与删除方式。旧版“全部默认仅本地”文案不直接沿用。

管理员默认查看调用数、任务状态、耗时、错误码和资源用量，不在运营日志中记录私密正文或图片提示词；现有管理员内容访问能力必须审计，不将旧实现视为已满足此承诺。

保留旧 localStorage v2 和关系档案，不自动转换、不发送到角色生成或剧情模型；新增数据使用独立命名空间、表和向量集合。提供旧数据导出入口。删除故事时删除回合、记忆和私有素材引用，异步清理索引及孤立文件，界面区分已删除与后台清理中；备份保留规则需在发布时按真实部署披露。

首版面向 Linux/Node 部署，不部署 Sites。旧 Sites 适配器维持原状，新能力需通过服务端 capability 标识后才展示，避免新前端调用未实现的接口。

## 10. 验收与分期

一期闭环：从描述创建人物 → 确认形象 → 进入第一幕 → 发起两轮自由对话与一次分支选择 → 刷新后恢复 → 在回忆册找到并编辑对应记忆。

二期扩展：更多表情、其余场景、丰富章节及关系确认后日常。多角色、换装商店、TTS、无限剧情分支不进入一期。

上线门槛：

1. 两个账号彼此访问人物、回合、素材和记忆均被拒绝；不同故事版本检索隔离。
2. 未成年角色设定不进入恋爱故事创建；用户角色身份及偏好修改按新版本处理。
3. 设定确认后跨场景人物形象保持一致；图片失败可恢复且不重复结算。
4. 重复发送、断流、刷新、取消、重试不产生重复事件，不跳过剧情前置条件。
5. 连续两轮录音、慢 ASR、句读失败、手动修改与迟到响应的场景均有测试。
6. 375px 移动端、桌面、中英文、键盘和减少动态效果下操作完整，无文字截断。
7. 使用脚本化对话检查身份一致、事实来源、重复初遇、分支越界、记忆删除后重新出现等问题。
8. 在目标 2 核 4G 主机测量语音等待、文本首字时间、图片任务排队时间与错误率；实际基线记录后再制定性能承诺，不用本地单元测试代替生产性能验证。

首版按独立实施计划开发；完整规格中的后续项不得宣称已经上线。
