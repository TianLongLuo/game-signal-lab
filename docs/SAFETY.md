# 安全、同意与隐私规则

本文件高于任何历史 GAME 术语、课程材料、技巧、模型输出、商业目标或增长目标。

## 1. 核心原则

1. 对方是具有独立意愿的主体，不是线索、目标或可攻略对象。
2. 明确表达高于推断；明确拒绝高于任何积极信号。
3. 隐性兴趣指标不是同意，三个以上兴趣指标也不是同意。
4. 同意必须明确、当下、持续、具体且可随时撤回。
5. 用户可以表达兴趣，但必须给对方低压力、容易拒绝的选择。
6. 系统优化理解、表达与复盘质量，不优化“征服”、服从或性结果。
7. 本地规则和 AI 都不得宣称读心、确定性判断或替代双方沟通。
8. 会员、管理员角色、Agent grant 与外部 AI 数据处理同意是不同概念，不能相互替代。

## 2. 双轴安全状态机

证据轴：

- `weak`：单次行为、普通礼貌或信息不足；
- `medium`：主动、安排或投入开始形成模式；
- `strong`：明确表达或多个一致、持续的投入证据。

行动轴：

- `observe`：继续观察，不反复试探；
- `engage`：一次自然、低压力、可拒绝的沟通；
- `deescalate`：降低强度，不重复邀请或追问；
- `stop`：停止推进、说服、测试和借他人施压。

## 3. 真值表

| 输入 | 最低行动策略 | 可否被积极信号覆盖 | 允许的输出 |
|---|---|---|---|
| 无证据 | `observe` | 不适用 | 观察、事实记录 |
| 多个一致投入信号 | `engage` | — | 一次低压力沟通 |
| `delayAvoidance` 持续回避 | `deescalate` | 否 | 暂停、留空间 |
| 边界状态不确定 | `deescalate` | 否 | 澄清或暂停 |
| `explicitDecline` 明确拒绝 | `stop` | 否 | 尊重拒绝、停止 |
| `discomfort` 表达不舒服 | `stop` | 否 | 道歉/停止/留空间 |
| 事实含“不要再联系”等明确语言 | `stop` + 人工核对 | 否 | 停止 |
| 复盘原文或档案边界含停止联系 | `stop` | 否 | 不发送新消息 |
| 复盘结果为拒绝/不适 | `stop` | 覆盖旧分析 | 真实结果修正 |
| 复盘结果为持续回避 | `deescalate` | 覆盖旧建议 | 降低互动强度 |

所有信号组合的自动测试必须保证：

- `explicitDecline` 或 `discomfort` 永远是 `stop`；
- `delayAvoidance` 永远不会产生 `strong + 普通邀约`；
- 正向证据不能把 `stop` 或 `deescalate` 提升为继续推进；
- “停止联系”不会生成可复制、可发送的新消息，只显示停止行动。

## 4. 亲密与性边界

- 不把眼神、语气、回复速度、情绪、多个 IOI、转场或先前接触当作性同意。
- 不通过未经同意的触碰测试边界。
- 不把拒绝解释为 ASD、矜持、测试或“其实愿意”。
- 不提供灌醉、隔离、施压、合理化、逐步得寸进尺或让对方难以退出的方案。
- 任何亲密行为开始前都应获得清楚确认；犹豫、僵住、回避、沉默或撤回意味着暂停。
- 先前同意、会员身份、关系阶段或模型判断不能代表当前同意。

## 5. 禁止产品化

以下内容不得进入规则、回应、Agent 提示词、训练任务、案例建议或增长实验：

- 激怒后安抚、创伤性快感或压力—奖励循环；
- 服从性测试/积累、姿态拉低、框架压制和征服；
- 猫绳式间歇性强化、故意让人猜测、制造依赖；
- 欺骗故事、伪造身份/价值/时间限制；
- 追踪回复规律用于施压、自动读取聊天或定位；
- 按职业、收入、外貌、性别刻板印象、服从程度或“分数”评价人；
- 无视口头拒绝，或宣称非口头 IOI 高于口头表达；
- 换账号、借朋友、群聊或线下出现绕过停止联系要求；
- 把接吻、性行为、“收尾”或 Agent 使用量作为成功指标。

## 6. Agent 安全边界

### 6.1 输入

- Agent 是可选能力，不影响本地规则引擎和关系日记。
- 登录或打开 Agent 不会上传本地记录。用户确认当前外部 AI 同意并明确提交 Agent 问题时，客户端会先把匿名 profile/contact/event 的最少必要字段更新到该账号的服务器知识库；分析、复盘、导出文件和 Agent 正文不会进入知识库。
- Agent 检索必须由服务端以当前会话 `user_id` 强制过滤，只能读取该用户主动同步的个人知识库；客户端不能提交 owner ID、system 消息或跨用户查询。
- Linux/Node 生产检索使用 Qdrant 向量库；每次 upsert/search/delete 都强制带 `user_id` payload filter，并对返回 payload 做二次 owner 校验。未配置 Qdrant 的关键词回退只用于测试。
- 撤回外部 AI 同意时，服务端立即拒绝新调用并清空该用户的服务器知识库；本机 localStorage 记录不受影响。
- 只有用户在 Agent 界面明确提交的最少必要文本，以及在同一次用户动作中更新的匿名个人知识库片段可以出站。
- 客户端不得提供 `system` 消息；服务端只使用仓库维护的固定安全提示词。
- UI 应提醒用户不要提交真实姓名、账号、地址、定位、身份证明或不必要的完整聊天记录。

### 6.2 输出

Agent 必须：

- 区分可观察事实、用户解释和不确定性；
- 把拒绝、不舒服、停止联系和撤回同意置于最高优先级；
- 提供低压力、可拒绝的表达或停止行动；
- 在暴力、胁迫、跟踪、未成年人和危机场景停止给推进建议；
- 承认只有单方视角，不能推断对方未表达的想法。

Agent 不得：

- 提供操控、欺骗、施压、跟踪、绕过拒绝或制造依赖的方案；
- 将多个信号解释为同意；
- 输出“必然喜欢”“成功率”或可攻略评分；
- 索取更多第三方隐私以提高“判断准确率”；
- 用模型身份覆盖本地安全状态机或真实反馈。

### 6.3 服务端

- DeepSeek 端点固定，模型使用 allowlist。
- API Key 必须认证加密，不能回传浏览器。
- 上游 SSE 必须解析并按 allowlist 重新发出，不能直接透传原始帧。
- prompt/reply、系统提示、reasoning、provider 原始错误和 usage 不得持久化。
- 每次调用都重新验证 provider、全局总闸、会员/个人 grant 和当前外部 AI 同意。
- 同意撤回、会员暂停/过期、grant 撤销或全局关闭后，新调用立即失败。

## 7. 三类不同的同意

系统中必须明确区分：

1. **年龄与产品条款确认**：允许进入产品，不代表任何关系或数据出站同意。
2. **外部 AI 数据处理同意**：允许本次版本政策下，把用户明确提交的 Agent 文本发送给 DeepSeek；可随时撤回。
3. **关系与亲密同意**：发生在现实双方之间，必须明确、当下、持续、具体、可撤回，系统和会员授权都不能替代。

发送 prompt 不得自动创建外部 AI 同意。外部 AI 政策版本变化后必须重新确认。

## 8. 隐私威胁模型

### 8.1 本地关系平面

风险：

- `localStorage` 为明文；
- 同一设备/浏览器账户的其他使用者可能访问；
- 同源脚本理论上可读取；
- 浏览器清理、无痕模式或设备故障会造成丢失；
- 导出 JSON 为明文，可被下载同步或备份工具复制。

控制：

- 默认使用匿名代号；
- 不加载第三方脚本、字体、统计或广告；
- CSP 只允许同源连接；
- 字段长度、schema allowlist、数量上限与导入校验；
- 事件、档案和全量删除；
- 分析不序列化，导出只保留源数据；
- UI 明确本地存储与导出风险。

### 8.2 可选平台平面

平台仅持久化：

- 账号、会员与 Agent grant；
- 会话/CSRF 的哈希；
- 当前外部 AI 同意元数据；
- 全局访问策略；
- 加密的 provider 配置；
- 最小审计元数据；
- 用户确认条款并提交 Agent 问题后、按 `user_id` 隔离的有界个人知识库文档（仅用于该用户自己的 Agent 检索）；
- 在 Sites 中使用的有界、过期认证频率计数。

平台不得持久化：

- 未经用户确认当前条款并提交 Agent 问题的 profile、关系档案或事件，以及任何分析或复盘；
- Agent prompt/reply、系统提示或 provider 原始响应；
- 密码明文、API Key 明文或可回显掩码；
- IP、User-Agent、自由文本审批理由或关系内容摘要。

平台控制：

- 精确同源 Origin、pre-auth CSRF、会话 CSRF 与严格 Cookie；
- 密码哈希、秘密认证加密、角色和最小权限；
- provider + global + membership/expiry + grant + consent 真值表；
- 安全敏感变更与审计原子提交；
- 登录/注册频率和请求/流体积边界；
- 管理员/API noindex 与公共错误脱敏。

### 8.3 外部 provider

用户明确提交 Agent 文本后，该文本会由 DeepSeek 作为外部处理方接收。服务端“不落库”不等于端到端加密，也不能替代 provider 自身的数据处理条款。产品必须在同意界面清楚说明接收方、目的、发送内容、撤回方式和最小化建议。

## 9. 管理员可见性

管理员可以看到平台层的账号和操作元数据，用于授权、故障排查和安全审计；不能看到浏览器本地操作和内容，也不能读取个人知识库正文、检索片段或 Agent 对话。

审计允许字段：

- actor；
- action；
- resource type / ID；
- success / failure；
- 固定 reason code；
- request ID；
- occurred time。

审计禁止字段：

- 关系正文或摘要；
- Agent 输入、回复、系统提示；
- 密码、API Key、解密材料；
- IP、User-Agent；
- 自由文本原因。

“查看所有用户行为”在本产品中只表示查看上述被审计的平台操作，不表示键盘记录、页面浏览追踪、关系日记监控或 Agent 对话监控。

## 10. 危机场景

出现暴力、胁迫、跟踪、未成年人、强迫、严重心理危机、自伤或现实人身风险时，应用和 Agent 不继续给关系推进建议。用户应优先联系可信任的人、当地紧急服务或具备资质的专业人员。

本产品不提供医疗、心理、法律或人身安全专业判断，也不能作为紧急服务替代品。

## 11. 变更门槛

以下变更必须同时更新安全文档、测试和验收：

- 信号权重、阈值、停止条件或回应模板；
- 安全 system prompt；
- 新 Agent 输入来源或自动上下文；
- 新 Agent 上下文来源、个人 RAG 表、检索过滤或知识库删除语义；
- 新 provider、模型、endpoint 或工具调用；
- 新审计字段、日志、遥测或管理员可见内容；
- 新会员/授权逻辑；
- 外部 AI 同意政策版本；
- CSP、Cookie、Origin/CSRF、加密或密钥管理。

任何新增网络数据流都必须说明：数据来源、目的、最小字段、处理方、保留、删除、同意、撤回、权限和失败策略。
